# 논문 적용 메모 (2205.13170v2) — semantic-uplink-rpi5 (LinUCB 업링크 정책)

- 대상 논문: **Distributed Contextual Linear Bandits with Minimax Optimal Communication Cost** (arXiv:2205.13170v2)
- 작성 목적: 현재 프로젝트의 **LinUCB 기반 (tau, kbits) 선택** 로직을 “이론/가정/한계/확장 방향(통신비용)” 관점에서 점검하고, 보고서/README에서 **근거로 인용 가능한 수준**으로 정리.

> 주의: 이 논문은 **(다중 에이전트) 분산/연합 환경에서의 학습 통신비용**을 다룬다.  
> 본 프로젝트의 “Rate(전송률)”는 **데이터 평면(uplink payload) 비용**이고, 논문은 **제어 평면(학습/동기화 메시지) 비용**이 중심이다.  
> 따라서 “그대로 적용”이 아니라, **확장 시나리오** 및 **배치(elimination) 설계 포인트**를 차용하는 관점으로 읽는 것이 정확하다.

## 1) 프로젝트 현재 LinUCB 구현 스냅샷 (코드 확인 기준)

### 1.1 상태(컨텍스트) 벡터
`edge/policy/linucb.py`의 `build_context()`는 다음 5개 상태를 정규화하고, bias(상수 1)를 붙여 **6차원 컨텍스트**를 만든다.

- `aoi_ms` → `aoi_ms / aoi_max_ms`
- `res`(재구성 오차/잔차) → `abs(res) / res_mae_max`
- `res_var` → `sqrt(res_var) / 100`  *(변동성 스케일링)*
- `loss` → `loss / loss_max`
- `q_len`(큐 길이) → `q_len / q_max`
- + bias 1.0

> 결과적으로 각 항은 대략 0~1 스케일(또는 그 근처)로 들어간다.  
> 이건 “컨텍스트 boundedness” 가정(선형 밴딧에서 일반적으로 필요한 전제)에 유리한 구현이다.

### 1.2 팔(arms)과 행동
본 프로젝트의 LinUCB는 팔을 **(tau, kbits)** 조합으로 정의해 선택한다.
- `tau`: EWMA 트리거 임계값(잔차/품질 기반)
- `kbits`: 전송 kbits(압축/전송량 제어)

### 1.3 보상 설계 (실측 결과 기반, 최대화)
`observe_outcome()`에서 보상은 다음 형태로 계산된다.

- `MAE_norm = abs(res)/res_mae_max`
- `AoI_norm = aoi_ms/aoi_max_ms`
- `Rate_norm = tx_kbits/kbits_max`
- `reward = -(w_aoi*AoI_norm + w_mae*MAE_norm + w_rate*Rate_norm) / (w_aoi+w_mae+w_rate)`

즉, **AoI / MAE / Rate를 모두 낮추는 방향**이 보상 최대화(덜 음수)로 귀결된다.

### 1.4 안전가드(safety)
다음 조건을 만족하면 **학습된 선택을 무시하고 safe arm을 강제**한다.

- `aoi_ms >= aoi_max_ms` **또는**
- `abs(res) >= res_mae_max`

(옵션에 따라 AoI 초과 시 강제 emit도 존재)

### 1.5 비교 정책(요약)
- `periodic`: 사실상 “매 샘플 전송”에 가깝도록 런타임에서 `tau`를 음수로 처리해 `abs(res)>tau`가 항상 참이 되게 함.
- `fixed_tau`: 고정 임계값 기반 EWMA 트리거.
- `adaptive(LinUCB)`: 상태→팔(tau,kbits) 선택 + 안전가드.

## 2) 논문 문제 설정을 프로젝트 언어로 재정의

논문은 N개의 에이전트(노드)가 동시에 학습하는 **분산 컨텍스트 선형 밴딧**을 다룬다.

- 에이전트: `i ∈ {1,…,N}`
- 시점: `t ∈ {1,…,T}`
- 각 에이전트는 시점 t에 **팔 후보들의 feature set** `X^i_t = {x^i_{t,a} : a∈[K]}`를 관측
- 팔 `a`를 선택하면 확률적 보상 `y^i_t`를 관측
- 기대보상은 선형: `E[y | x] = <θ*, x>` (노이즈 포함)

프로젝트에 “개념적으로” 매핑하면:

| 논문 | 본 프로젝트(현재 구현) |
|---|---|
| 에이전트 i | 엣지 노드 (현재는 사실상 N=1; 확장 시 다중 엣지 가능) |
| 팔 a | (tau, kbits) 조합 |
| feature x_{t,a} | 상태( AoI, res, var, loss, q_len ) 정규화 + bias |
| 보상 y | -(AoI, MAE, Rate 가중합) |
| 통신비용 | (논문) 학습/동기화 메시지 / (프로젝트) LoRa uplink payload + (옵션) 학습 로그/파라미터 업링크 |

## 3) 논문 핵심 결과: “좋은 regret을 내려면 통신을 최소 Ω(dN) 해야 한다”

### 3.1 하한(Theorem 1): minimax regret 달성의 통신 하한
논문은 다음 정보를-이론적(lower bound) 결론을 제시한다.

- 어떤 분산 알고리즘이 **최적 수준의 regret** `~ O(√(dNT))`를 달성하려면,
- 기대 통신량(비트 기준)이 **최소 Ω(dN)** 이상 필요하다.

해석:
- 분산/연합에서 “학습 공유를 거의 안 하면서” 단일 에이전트 최적 regret을 얻는 건 불가능.
- d(특징 차원)와 N(노드 수)에 **선형**으로 비례하는 수준의 정보 교환이 ‘필수 비용’이 된다.

> 프로젝트 적용:
> - 현재는 N=1이라 이 하한이 직접적 제약은 아니다.
> - 하지만 “향후 다중 엣지로 확장할 때”는 **학습 동기화를 완전히 피하면서 성능만 얻겠다**는 주장 자체가 성립하지 않는다.
> - 보고서/포트폴리오 관점에서는 “확장 시 제어 평면 오버헤드를 이론적으로 하한까지 줄이는 설계”를 목표로 둘 때 근거로 쓸 수 있다.

### 3.2 상한(Theorem 2): DisBE-LUCB의 (거의) 최적 통신
논문은 **DisBE-LUCB**라는 알고리즘을 제안하고 다음을 보장한다.

- Regret: `~ O( √(dNT) * polylog(...) )`
- 통신비용(실수 개수 기준): `O( dN * log log(NT/d) )`

즉, 통신은 `Ω(dN)` 하한과 비교해 **로그로그 정도만 더** 쓰고, regret도 거의 최적.

> 프로젝트 적용:
> - “통신을 줄이려면 배치(batch)로 묶고, 배치별로 필요한 최소 통계만 공유”라는 구조가 핵심.
> - 단일 노드라도 (tau,kbits) 후보가 많거나 환경이 급변하지 않는 구간에서는 **팔 후보를 배치 단위로 제거(eliminate)** 하는 방식이 의사결정 안정성을 높일 수 있다.  
>   다만, 본 프로젝트는 안전가드/강제 emit이 있어 elimination의 효과를 데이터로 확인해야 한다(추정 금지).

### 3.3 비트(quantization) 관점의 보정: rounding ε₀
논문은 통신비용을 “실수 개수” 대신 “비트 수”로 해석하기 위해,
각 에이전트가 서버로 보내는 벡터를 **정밀도 ε₀로 반올림**하는 변형을 다룬다.

- 적절히 `ε₀ = O( 1/(N√(dT)) )` 정도로 잡으면
- regret 보장은 유지하면서,
- 비트 단위 통신비용도 `~ O(dN log log(NT/d) log(dNT))`로 정리된다.

> 프로젝트 적용:
> - 향후 “엣지→collector로 학습 통계(예: arm별 sufficient statistics)를 전송”하는 구조를 추가할 때,
> - **부동소수점 원본을 그대로 보내지 말고**, 오차 상한을 정해 **양자화/반올림**으로 줄이는 설계를 정당화할 수 있다.
> - 단, 본 프로젝트에서 실제 radio payload의 bit budget과 ε₀의 관계(정규화 스케일/오차 누적)를 별도 실험으로 묶어야 한다.

## 4) DisBE-LUCB 구조 요약 (서버 존재)

핵심은 “**M개의 배치**로 시간을 나누고, 배치마다 통신은 1회(또는 소수 회)로 제한”하는 것.

### 4.1 배치 m에서 에이전트 i가 하는 일(요지)
1. 배치 m 시작 시점에 살아남은 팔 집합을 계산 (이전 배치까지의 elimination 결과)
2. 배치 절반 구간 동안 **고정된 탐색 정책**으로 팔을 샘플링 (ExpPol 서브루틴 사용)
3. 배치 중간에, 에이전트는 `u^i_m = Σ x_t y_t` 형태의 **d차원 요약 벡터**를 서버로 보냄
4. 서버는 `Σ_i u^i_m`를 다시 브로드캐스트
5. 에이전트는 이를 이용해 파라미터/통계(Λ, θ 등)를 업데이트하고,
6. **새 confidence interval**로 팔을 추가 제거(eliminate)

논문이 강조하는 포인트:
- 기존 confidence interval을 그대로 쓰면 통신이 d배 더 커질 수 있어,
- **새 confidence interval(Lemma 2)**를 설계해 각 에이전트가 **d개 값(u^i_m)만 전송**해도 되게 만든다.

> 프로젝트 적용:
> - “노드 간 학습 공유”를 만들 경우, d차원 요약(벡터)만 전송하는 설계는 LoRa 같은 협대역 환경에 특히 유리하다.
> - 반대로, 매번 d×d 공분산(행렬)까지 보내는 접근은 payload 비용이 급증한다(현실성 낮음).

## 5) DecBE-LUCB 구조 요약 (서버 없음)

서버 없이 **에이전트 간 네트워크(gossip/consensus)**로 집계를 맞추는 버전이다.
- 통신 그래프의 연결성(2번째 고유값 등)에 의해 성능/비용이 영향을 받는다.
- 논문 부록의 **가속 커뮤니케이션(Algorithm 3)** 절차로 합의 속도를 개선한다.

> 프로젝트 적용:
> - LoRa mesh 형태로 확장하는 경우(서버 없는 토폴로지) 이 방향이 의미가 있다.
> - 단, LoRa에서의 다중 홉/재전송/충돌이 합의 지연을 크게 만들 수 있으므로,
>   DecBE-LUCB의 “통신 라운드 수 S”를 실제 PHY/MAC 지표로 환산하는 작업이 필요하다.

## 6) 본 프로젝트에 “직접” 이식 가능한 요소와, 현재로선 보류해야 할 요소

### 6.1 바로 쓸 수 있는 요소(설계 원칙)
- **통신을 줄이려면 배치화**: “매 라운드 동기화” 대신 “배치별 요약 통계 전송”으로 설계해야 한다.
- **요약 통계는 d차원으로 제한**: 벡터 `Σ x y` 수준의 sufficient statistics만으로 협업이 가능하다는 방향성을 제공한다.
- **비트 관점(양자화) 정당화**: ε₀를 통해 “얼마나 거칠게 보내도 되는지”를 regret bound로 해석하는 틀을 준다.

### 6.2 보류해야 할 요소(프로젝트-논문 간 가정 불일치)
- 논문 가정은 `E[y|x]=<θ*,x>` 형태의 선형 모델 + (대체로) 정상성/확률적 컨텍스트 가정이다.
- 본 프로젝트의 reward는 AoI/MAE/Rate 기반이며,
  - AoI는 큐/스케줄링/네트워크 상태에 의해 비선형/지연이 섞일 수 있고,
  - MAE는 압축/재구성 모델 및 입력 분포 변화(개체/환경) 영향을 강하게 받는다.
- 따라서 “minimax regret 보장”을 프로젝트에 그대로 주장할 수 없다.
  - 이 문서는 **‘근거로 인용 가능한 통신-학습 트레이드오프 결과’**를 제공하는 용도다.

## 7) 보고서/README에 넣을 수 있는 ‘정확한 문장’(과장 금지)

- “분산 컨텍스트 선형 밴딧에서 최적 수준의 누적 regret을 달성하려면, 기대 통신량이 최소 Ω(dN) 이상 필요하다는 정보이론적 하한이 존재한다(Theorem 1).”
- “해당 하한에 로그로그 정도만 초과하는 통신으로, 거의 최적 regret을 달성하는 배치 제거 기반 알고리즘(DisBE-LUCB)이 제안되어 있다(Theorem 2).”
- “향후 다중 엣지로 확장 시, 매 라운드 파라미터/행렬을 동기화하는 설계는 LoRa uplink의 bit budget에서 비현실적일 가능성이 높으며, 배치별 d차원 요약 통계 전송 및 양자화(ε₀-precision rounding) 같은 통신 절약 기법이 설계 후보가 된다.”

## 8) 메모: 본 프로젝트 KPI(데이터 평면)와 논문(제어 평면)을 연결하는 방법

현재 프로젝트에서 “Rate 감소”는 uplink payload(데이터 평면) 절감이 1차 관심사다.  
논문은 학습 공유를 위한 메시지(제어 평면) 절감이 목적이다.

둘을 연결하려면 “학습 공유가 필요한가?”가 먼저 결정되어야 한다.

- N=1(단일 엣지) 유지: 논문 결과는 직접 KPI에 들어가기 어렵고, “배치 제거/양자화”를 **참고 설계 포인트**로만 활용.
- 다중 엣지로 확장: 아래 두 비용을 분리해 KPI 설계 가능
  - 데이터 평면: uplink payload rate / energy
  - 제어 평면: 학습 통계/정책 동기화 메시지 bit-rate

이때 논문은 **제어 평면 KPI의 하한(Ω(dN))**과 **근접 달성 알고리즘 구조**를 제공한다.
