# (논문 정리·프로젝트 적용) Learning in Distributed Contextual Linear Bandits Without Sharing the Context  
- 원문: Osama A. Hanna, Lin F. Yang, Christina Fragouli, arXiv:2206.04180v1 (2022-06-08)  
- 본 문서 목적: **“의미 기반 업링크 최적화(LoRa/엣지) + LinUCB 정책”** 프로젝트에 바로 연결되도록, 논문 내용을 *운영/재현/통신비트 관점*으로 재구성한 MD 노트

---

## 0. 이 논문이 우리 프로젝트에 “직접” 맞닿는 지점
프로젝트의 실체는 다음 형태로 정리된다.

- **분산(Distributed)**: 엣지 노드(송신기)에서 컨텍스트(상태/특징)를 관측하고, 게이트웨이/서버(중앙 학습기)가 정책 파라미터(θ)를 학습한다.
- **업링크가 병목(Uplink bottleneck)**: LoRa 업링크는 페이로드/에어타임/전력/채널 점유 등 제약이 크다. 컨텍스트 벡터(차원 d)가 커질수록 “상태 전달”이 곧 비용이 된다.
- **컨텍스트 공유의 비현실성**: 중앙 학습기가 매 스텝마다 `X_{t,a}`(모든 액션에 대한 특징 벡터)를 원본 그대로 받는 설계는 실전에서 쉽게 깨진다.

이 논문은 위 상황을 **문제 정의 자체로** 잡는다.

> “에이전트(엣지)는 컨텍스트를 보지만 학습기는 컨텍스트를 못 본다. 업링크로 제한된 비트만 보낼 수 있다. 그래도 LinUCB급 후회(regret)를 유지할 수 있나?”

---

## 1. 논문 설정(문제 정식화) — 프로젝트 용어로 번역

### 1.1 시간, 액션, 컨텍스트, 보상
- 시간: `t = 1..T`
- 액션(arm): `a ∈ A`  
  - 프로젝트 매핑 예시(“예시”가 아니라 선택지의 틀):
    - (통신 파라미터) SF/CR/BW/TxPower 중 선택, 혹은 재전송 정책
    - (의미 압축) 압축 레벨/샘플링 레이트/semantic filter 강도
- 컨텍스트(특징 벡터): `X_{t,a} ∈ R^d`  
  - 논문은 **액션별 특징 벡터가 존재**한다고 둔다. (즉, 컨텍스트는 `{X_{t,a}}_{a∈A}`의 집합)
  - 프로젝트에선 “각 후보 설정 a를 적용했을 때의 상태 특징”을 벡터로 만든다고 보면 된다.
- 선형 보상 모델:
  \[
  r_t = \langle X_{t,a_t}, \theta^\* \rangle + \eta_t
  \]
  - `θ* ∈ R^d`는 미지(고정) 파라미터  
  - `η_t`는 조건부 0-평균, sub-Gaussian 계열 잡음

### 1.2 목표: 후회 최소화
\[
R_T = \sum_{t=1}^{T} \left(\max_{a\in A}\langle X_{t,a},\theta^\*\rangle - \langle X_{t,a_t},\theta^\*\rangle \right)
\]
이 후회를 **정보가 완전한(컨텍스트 공유 가능)** 표준 LinUCB급인
\[
\tilde{O}(d\sqrt{T})
\]
수준으로 유지하면서, 업링크 비트 `B_t`를 최소화하는 게 핵심이다.

## 2. 논문의 핵심 결과(우리에게 필요한 부분만 “정량”으로)

논문은 두 경우를 분리한다.

### Case A) 컨텍스트 분포를 학습기가 “이미” 알고 있는 경우
- **컨텍스트 전달 0비트**
- 보상은 **1비트**(확률적 양자화)만 업링크로 전송
- 그럼에도 후회는 LinUCB급 \(\tilde{O}(d\sqrt{T})\) 유지

해석:
- “상태 자체를 보내지 않아도” 학습이 가능하다는 결과.
- 실제 프로젝트에선 “컨텍스트가 어떤 분포를 따른다”를 실험/사전 측정/모델로 확보할 수 있는 경우에만 적용 가능.

### Case B) 컨텍스트 분포를 모르는 경우(현장 기본값)
- 컨텍스트당 **약 5d 비트** + 보상 1비트로 충분
- 후회는 동일하게 \(\tilde{O}(d\sqrt{T})\) 유지
- 논문이 제시하는 상한(업링크 총 비트):
  \[
  B_t \le 1 + \log_2(2d+1) + 5.03d
  \]
  (상수까지 박아 둔 형태라, LoRa 페이로드/에어타임 계산에 바로 투입 가능)

## 3. 공통 도구: 확률적 양자화 SQ(Stochastic Quantizer)

논문은 “정확한 재구성” 대신, **학습에 필요한 통계량(특히 LS 업데이트)을 망치지 않는** 방향으로 양자화를 설계한다.

### 3.1 SQ의 핵심 성질
- 입력을 구간/레벨로 스케일한 뒤, 바닥/천장 중 하나로 랜덤하게 올림/내림  
- 중요한 보장:
  - **편향 없음(Unbiased)**: \(\mathbb{E}[\mathrm{SQ}(x)\mid x]=x\)
  - 오차 상한: \(|\mathrm{SQ}(x)-x|\)가 레벨 간격으로 제한됨

프로젝트 관점:
- “컨텍스트를 ‘복원’할 생각으로 압축하지 말고”
- “θ 업데이트(=선형 추정)가 망가지지 않는 형태로 통계량을 보존”하는 게 포인트다.

## 4. 알고리즘 1 (컨텍스트 분포 Known) — 0-bit context 설계의 구조

### 4.1 무엇이 ‘known’이어야 하나?
- 각 액션 `a`에 대해 `X_{t,a} ~ P_a`라는 **분포 형태**를 학습기가 알고 있어야 한다.
- “컨텍스트의 실현값”은 몰라도 된다.

### 4.2 큰 아이디어: 멀티-컨텍스트를 “싱글-컨텍스트 선형 밴딧”으로 축소
논문은 다음 함수를 정의한다.

\[
X^\*(\theta)=\mathbb{E}_{\{x_a\sim P_a\}}\left[\arg\max_{x\in\{x_a:a\in A\}}\langle x,\theta\rangle\right]
\]

그리고 싱글-컨텍스트 밴딧 알고리즘 \(\Lambda\)(예: LinUCB)를 다음 액션 집합으로 돌린다.

\[
\mathcal{X}=\{X^\*(\theta)\mid \theta\in\Theta\}
\]

핵심은:
- \(\Lambda\)가 고르는 \(x_t\)는 실제로 “플레이되는 액션의 특징”이 아니다.
- 학습기는 \(x_t\)를 통해 \(\hat\theta_t = (X^\*)^{-1}(x_t)\)를 만들어 **다운링크로 에이전트에 보낸다**.
- 에이전트는 실제 컨텍스트를 보고 greedy로
  \[
  a_t = \arg\max_{a\in A}\langle X_{t,a},\hat\theta_t\rangle
  \]
  를 선택한다.
- 에이전트가 업링크로 보내는 건 **보상 1비트**뿐.

### 4.3 프로젝트에 적용할 때의 현실 체크
이 방법이 “뻥”처럼 보이는 이유는, 분포를 안다는 가정이 빡세기 때문이다.  
프로젝트에선 다음 중 하나를 만족할 때만 후보가 된다.

- (오프라인 교정) 각 설정 a에 대해 **컨텍스트의 통계가 안정적으로 추정 가능**  
  예: 특정 SF/TxPower에서 RSSI/SNR/성공확률이 일정 분포를 따르고, 계절/환경 변화가 작음
- (모델 기반) 전파/노이즈 모델로 `P_a`를 충분히 근사하고, 근사 오차가 작음  
  논문은 분포 오차가 \(\epsilon\)일 때 후회 페널티가 어떻게 붙는지도 제시한다:
  \[
  \tilde{O}(d\sqrt{T} + \epsilon T \sqrt{d})
  \]
  즉, 분포 근사가 구리면 장기적으로 선형 항이 튀어나온다.

## 5. 알고리즘 2 (컨텍스트 분포 Unknown) — “≈5d 비트” 설계의 실전 가치

현장형 프로젝트에서 우리가 주로 쓰는 건 이쪽이다.

### 5.1 알고리즘 2가 풀려는 진짜 문제
LinUCB/선형 밴딧의 업데이트는 대체로 다음 sufficient statistics로 귀결된다.

- \(V_t = \sum_{i=1}^{t} X_{i,a_i}X_{i,a_i}^\top\)
- \(u_t = \sum_{i=1}^{t} r_i X_{i,a_i}\)
- \(\hat\theta_t = V_t^{-1}u_t\)

따라서 “컨텍스트를 보내는 것”은 결국
- `X_{t,a_t}`를 얼마나 잘 전달하느냐(=u 업데이트)
- `X_{t,a_t}X_{t,a_t}^T`를 얼마나 잘 전달하느냐(=V 업데이트)

이 두 개를 망치지 않도록 양자화를 설계하면 된다.

### 5.2 양자화 패킷(업링크) 구성
논문의 구성은 다음 4종 메시지다.

1) **부호(sign) 벡터** \(s_t = \mathrm{sign}(X_{t,a_t})\) : `d` bits  
2) **크기(magnitude) 양자화**:
   - \(m=\lceil\sqrt{d}\rceil\)
   - 각 좌표의 절댓값을 \(m|X|\)로 스케일 후 SQ로 정수화
   - 결과 벡터 \(X_t\)는 특정 집합 \(Q=\{x\in\mathbb{N}^d:\|x\|_1\le 2d\}\)에 속함
   - \(X_t\)는 \(h(X_t)\)로 열거(encoding)해 전송: 약 `log2|Q|` bits  
3) **대각(diagonal) 보정용 1비트/좌표**: \(e_t^{(2)}\) : `d` bits  
   - \(X^2_{t,a_t}\) (대각 성분)과 복원값의 제곱이 “편향”을 만들기 때문에, 그 차이를 1비트 확률 양자화로 보정  
4) **보상 1비트**: \(\hat r_t = \mathrm{SQ}_1(r_t)\) : `1` bit

최종적으로 총 비트는 \(B_t \le 1 + \log_2(2d+1) + 5.03d\).

### 5.3 중앙 학습기(게이트웨이/서버) 업데이트 로직
복원:
- \(\hat X_t = s_t \odot (X_t/m)\)
- \(\hat X^{(D)}_t = \mathrm{diag}(\hat X_t\hat X_t^\top) + e^{(2)}_t\) (대각 보정 포함)

업데이트:
- \(u_t \leftarrow u_{t-1} + \hat r_t \hat X_t\)
- \(\tilde V_t \leftarrow \tilde V_{t-1} + \hat X_t\hat X_t^\top - \mathrm{diag}(\hat X_t\hat X_t^\top) + \mathrm{diag}(\hat X^{(D)}_t)\)
- \(\hat\theta_t \leftarrow \tilde V_t^{-1}u_t\)

다운링크:
- 다음 에이전트에 \(\hat\theta_t\) 전송(논문은 다운링크 무제한 가정)

## 6. 프로젝트 매핑(LoRa + 의미 업링크 + LinUCB) — “그대로 가져오면 생기는 간극”까지 포함

### 6.1 시스템 역할 매핑
- 중앙 학습기(central learner): **수신기(pi1)/서버(back-end)**  
  - θ, V(또는 V^{-1}), u 유지
- 에이전트(agent): **송신기(pi2)/엣지 노드**  
  - 컨텍스트 관측, 액션 선택, 보상 관측 후 압축 메시지 업링크 전송

### 6.2 무엇을 컨텍스트로 잡을지(=d 차원 설계)
논문은 `||X||2 ≤ 1`을 가정한다. 프로젝트에선 다음을 강제해야 한다.

- 특징은 반드시 **정규화/클리핑**해서 \([-1,1]\) 또는 norm-ball에 넣는다.
- d가 커질수록 비트는 5d에 선형으로 증가한다.  
  → “컨텍스트를 늘리는 건 곧 업링크 비용”이라는 사실이 명시적으로 드러난다.

특징 후보(카테고리):
- 링크 품질: RSSI, SNR, 최근 ACK 성공률, 최근 재전송 횟수
- 트래픽/버퍼: 큐 길이, 샘플링 지연(AoI에 영향)
- 에너지: 배터리 잔량, 송신 전력 레벨
- 데이터 의미: 이벤트 강도/중요도, 압축 손실 허용도(semantic tolerance)

※ 여기서 “후보”를 실제 사용 차원으로 확정하려면, **로그로 상관/중복을 제거**해야 한다. (d 줄이는 게 곧 비트 절감)

### 6.3 액션 공간 A 정의(=정책이 제어하는 레버)
프로젝트에서 A는 “통신 파라미터” 또는 “의미 압축 파라미터”가 된다.

- 통신 레버 예:
  - SF 선택, TxPower 선택, CR 선택, 재전송 허용 횟수
- 의미 레버 예:
  - 압축 레벨(quantization step), 샘플링 주기, 이벤트 기반 송신/필터링

주의:
- 논문은 액션별 특징 \(X_{t,a}\)가 존재한다고 가정한다.  
  즉, 각 액션이 “상태를 다르게 본다”는 모델이다.
- 프로젝트에서 이 형태를 만들려면 보통
  - (예측형) “a를 적용했을 때의 성공확률/에어타임/에너지”를 feature로 넣거나
  - (구성형) \(X_{t,a} = \phi(\text{현재상태}, a)\) 같은 특징 생성 함수로 통일한다.

### 6.4 보상 r_t 설계(중요: 논문은 r∈[0,1] 가정)
가장 실전형은 다음:

- 성공/실패: `r_t = 1{ACK 수신}` → 1비트 그대로
- 혹은 연속형 보상(정규화 필요):
  - \(r_t = \alpha\cdot \mathrm{PDR} - \beta\cdot \mathrm{airtime} - \gamma\cdot \mathrm{energy}\)
  - 반드시 [0,1]로 스케일/클립해야 SQ1 전제가 맞다.

## 7. “LinUCB 정책”과의 접점: 이 논문이 주는 구현 선택지

### 선택지 1) 논문 알고리즘을 그대로 가져가기(가정까지 수용)
- Alg2는 에이전트가 greedy로 \(a_t=\arg\max \langle X_{t,a},\hat\theta_{t-1}\rangle\) 선택
- 탐색(exploration)은 **컨텍스트 분포의 다양성(Assumption 2)**에 기대는 형태

현실 리스크:
- 실제 무선/환경에서 컨텍스트 다양성이 부족하면, greedy가 빠르게 한쪽으로 쏠려 V_t가 잘 조건화되지 않을 수 있다.

### 선택지 2) “정책 결정은 LinUCB로, 컨텍스트/통계량 전달은 Alg2 양자화로”
실전에서는 보통 이게 더 안전하다.

- 중앙이 LinUCB의 (A=V, b=u) 업데이트를 하고
- 에이전트는
  - UCB 계산에 필요한 최소 파라미터(θ, V^{-1} 또는 confidence term에 필요한 것)를 다운링크로 받아
  - 로컬에서 \(a_t=\arg\max (\langle X_{t,a},\hat\theta\rangle + \beta\|X_{t,a}\|_{V^{-1}})\) 계산
- 업링크는 논문식으로 \(X_{t,a_t}\), diag 보정, 보상 1비트를 전송

다운링크 비용이 문제면:
- θ만 보내고 V^{-1}은 주기적으로만 보내거나
- V^{-1} 대신 근사(대각/저랭크)로 보내는 식으로 타협한다.

## 8. LoRa 패킷 설계 관점 체크리스트(“바로 구현”용)

### 8.1 비트 예산 빠른 산출
\[
B_t \approx 5.03d + \log_2(2d+1) + 1
\]

- d=8 → 약 5.03*8=40.24, log2(17)=4.09 → ~45.3 bits ≈ 6 bytes  
- d=12 → 약 60.4 + log2(25)=4.64 → ~66.0 bits ≈ 9 bytes

즉, “컨텍스트 전달” 자체는 LoRa 페이로드에서 **한 자릿수 바이트**로 떨어질 수 있다.  
(다만 실제 구현에서는 헤더/CRC/프레이밍 오버헤드가 붙는다.)

### 8.2 송신 메시지 필드(권장 구조)
- version (1)
- t mod N (1~2 bytes)
- d (1 byte) — 고정이면 생략
- payload:
  - s_t 비트열 (ceil(d/8) bytes)
  - h(X_t) 코드 (가변 비트열)  
  - e^{(2)}_t 비트열 (ceil(d/8) bytes)
  - r_hat (1 bit) — 다른 비트열에 pack
- optional: checksum

### 8.3 패킷 손실/재전송 처리
논문은 밴딧 관점(학습 관측 누락)을 따로 다루지 않는다.  
LoRa에서는 관측 누락이 곧 “학습 데이터 결손”이므로 아래 중 하나로 규정해야 한다.

- (단순) 패킷 드롭 시 해당 t는 스킵 → V,u 업데이트 없음
- (ACK 기반) 업링크 메시지는 ACK 필요, 실패 시 재전송
- (저장 후 배치) 노드가 최근 k개를 저장했다가 다음 성공 패킷에 함께 실어 보냄  
  (이 경우 “memoryless” 가정이 깨지지만, 실전에선 훨씬 안전)

## 9. Assumption 2(다양성/조건수) — 프로젝트에서 “검증 가능한 형태”로 바꾸기
Alg2의 분석은 아래 형태를 가정한다.

\[
\sum_{i=1}^{t} X_{i,a_i}X_{i,a_i}^\top \succeq \frac{c t}{d} I
\]

즉, V_t가 충분히 잘 조건화되어야 한다.

프로젝트에서 확인할 로그 지표:
- 매 t마다(혹은 윈도우마다) \(\lambda_{\min}(V_t)\) 추적
- 조건수 \(\kappa(V_t)\) 추적
- 특정 액션으로 쏠림(arm selection entropy) 추적

이게 깨지면:
- 탐색 항(UCB)을 강화하거나
- 액션 후보를 강제로 섞거나(ε-greedy)  
- 컨텍스트 설계를 바꿔서 독립성/분산을 확보해야 한다.

## 10. 결론: 이 논문을 프로젝트에 넣을 때 “쓸 수 있는 문장” (포트폴리오/보고서용)
- 업링크 병목을 선형 밴딧 문제 정의로 끌어내려, **컨텍스트 공유 없이도** LinUCB급 학습이 가능함을 보이는 연구를 기준 설계로 사용했다.
- 컨텍스트 분포를 모르는 현실 조건에서, 컨텍스트당 약 \(5d\) 비트 수준의 확률적 양자화로도 \(\tilde{O}(d\sqrt{T})\) 후회가 유지된다는 결과를 채택했다.
- 구현에서는 LS 통계량(V,u)의 **편향 없는 업데이트**가 깨지지 않도록, 단순 벡터 압축이 아니라 “학습 친화형(learning-aware) 양자화”를 설계 원칙으로 삼았다.
- LoRa 환경에 맞춰 d(특징 차원)과 비트 예산을 고정하고, 패킷 손실 시 관측 누락이 학습에 주는 영향을 로그 기반으로 관리했다.

## 11. 부록: 알고리즘 2 의사코드(프로젝트 구현용)
아래는 논문의 Alg2 흐름을 코드로 옮기기 위한 최소 의사코드다.

### Agent (송신 노드)
1. downlink로 θ_hat 수신
2. 현재 컨텍스트로 각 a에 대한 X_{t,a} 구성
3. a_t = argmax_a <X_{t,a}, θ_hat>
4. r_t 관측 (예: ACK=1 else 0; 또는 정규화된 연속 보상)
5. (X_{t,a_t} 양자화)
   - s_t = sign(X)
   - m = ceil(sqrt(d))
   - Xmag = SQ_m(m*abs(X))  # 정수 벡터
   - code = h(Xmag)
   - e2 = SQ_1^{[-3/m,3/m]}(X^2 - Xhat^2)  # 대각 보정
6. r_hat = SQ1(r_t)  # 1 bit
7. uplink로 (code, s_t, e2, r_hat) 전송

### Central learner (수신/서버)
1. uplink 메시지 수신
2. Xhat 복원, Xhat(D) 복원
3. u += r_hat * Xhat
4. Ṽ += Xhat Xhat^T - diag(...) + diag(Xhat(D))
5. θ_hat = inv(Ṽ) * u
6. 다음 t에 θ_hat downlink
